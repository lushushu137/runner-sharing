# 《Project Mosa》游戏策划师职责与剧情贴合玩法设计规范

## 1. 文档目的

本文件用于定义我在本项目中的游戏策划职责，并给出一套可执行的方法：  
将“故事情绪”转化为“玩家可直接感知的交互体验”，使每个场景的玩法都与剧情表达高度贴合（参考 Florence 的叙事交互思路）。

---

## 2. 角色定位

**我的角色：叙事交互型游戏策划师（Narrative Interaction Designer）**

核心目标不是“做更多系统”，而是做到：

1. 每个交互都服务剧情推进；
2. 每个操作都能传递角色关系和情绪变化；
3. 玩家在“玩”的同时自然“理解故事”。

一句话职责：

> 把故事中的情绪变化，翻译成玩家手上的动作与反馈。

---

## 3. 核心职责（职责清单）

### 3.1 故事拆解与情绪地图

- 将章节剧本拆成 Scene Beat（场景节拍）。
- 为每个节拍定义：
  - 场景目标（剧情要讲什么）
  - 情绪目标（玩家应感受到什么）
  - 关系变化（角色距离如何变化）
- 输出：《章节情绪地图》《场景节拍表》。

### 3.2 场景到玩法的映射设计

- 为每个关键场景设计 1 个“情绪隐喻交互”。
- 交互先回答“表达什么”，再决定“怎么操作”。
- 保证“玩家动词”与剧情语义一致（拖、拼、对齐、靠近、分离等）。

### 3.3 微交互节奏与时长控制

- 单个微交互时长建议：**15~60 秒**。
- 场景层节奏遵循：**叙事输入 -> 玩家动作 -> 反馈确认 -> 下一段叙事**。
- 避免长时间纯文本或长时间纯操作，保持交替节奏。

### 3.4 反馈语言统一（视觉/音频/文本）

- 成功反馈：清晰但克制，强调“关系推进”而非“得分”。
- 失败反馈：低惩罚、可恢复，避免破坏情绪沉浸。
- UI 文案尽量情境化，少用系统化术语（如“正确/错误”可改为“更贴近/仍有距离”）。

### 3.5 可玩性验证与迭代

- 负责玩法原型与可读性测试：
  - 3 秒知道目标
  - 10 秒开始有效操作
  - 1 分钟内完成单段微交互
- 通过试玩数据迭代（完成率、误操作、重试率、主观情绪评分）。

### 3.6 跨职能协同与验收

- 与程序协作：定义状态机、胜负条件、跳过逻辑、存档节点。
- 与美术协作：定义可读层级、交互焦点、情绪色彩变化。
- 与音频协作：定义 BGM 情绪曲线与 SFX 反馈层级。
- 输出验收标准并组织版本走查。

## 4. Florence 风格的设计原则（本项目适用）

1. **交互即叙事，不做分离式“小游戏插播”**。  
2. **操作复杂度跟随关系变化而变化**（关系紧张时更碎、关系顺畅时更流畅）。  
3. **少数高意义动作优先于大量低意义操作**。  
4. **失败是情绪表达，不是惩罚手段**。  
5. **UI 尽量“隐身”**，优先让画面、动作、声音本身讲故事。  
6. **每个场景只传递一个核心情绪**，避免表达目标混杂。

## 5. 基于当前故事的“场景-交互”设计方案（Chapter 1: Same Frequency）

> 当前章节结构：通勤开场 -> 咖啡店相遇 -> 记忆碎片 -> 对话排序 -> 结尾同步

### Scene A：通勤（introCommute）

- 剧情意图：Lin 处于封闭、重复、机械的日常状态。
- 情绪目标：压抑、隔离、节律单一。
- 交互提案：**“噪声过滤”微交互**
  - 玩家滑动降噪频段，逐步压低环境噪声。
  - 当噪声下降到阈值时，Mo 的声音轮廓第一次被“听见”。
- 叙事收益：玩家通过“主动过滤世界”体验 Lin 的心理状态。

### Scene B：咖啡店（introCafe）

- 剧情意图：陌生人从同处一桌到开始建立交流。
- 情绪目标：试探、犹豫、逐步靠近。
- 交互提案：**“桌面距离”微交互**
  - 玩家摆放杯子、笔记本、纸巾，调整两人之间的“安全距离”。
  - 过近会触发紧张反馈，过远会触发冷淡反馈，处于舒适区才推进对话。
- 叙事收益：通过空间距离直接表达社交边界变化。

### Scene C：记忆碎片（puzzle）

- 剧情意图：共同经历开始形成可被回忆的片段。
- 情绪目标：从零散到成形。
- 交互提案（在现有 Fragment Match 基础上升级）：
  - 每个碎片附带“情绪标签”（如迟疑、好奇、放松）。
  - 正确匹配后，背景逐层上色并出现短句回忆。
  - 错配不强惩罚，但会出现“记忆噪点”提醒。
- 叙事收益：拼图不再只是正确性判断，而是“共同记忆成像”过程。

### Scene D：对话排序（dialogue）

- 剧情意图：对话从尴尬变为自然。
- 情绪目标：节奏磨合、表达对齐。
- 交互提案（在现有 Dialogue Order 基础上升级）：
  - 第一层：排序句子先后（结构正确）。
  - 第二层：设置停顿/语气强弱（节奏正确）。
  - 当两层均达标，触发“同频”反馈（音画同步变化）。
- 叙事收益：玩家不仅“排对内容”，还“排对关系节奏”。

### Scene E：结尾（outro）

- 剧情意图：关系进入“初步同频”。
- 情绪目标：稳定、温暖、留白。
- 交互提案：**“双人节拍同步”短交互**
  - 玩家按左右节拍交替点击，维持一个共同脉冲。
  - 稳定 6~8 秒后，进入章节结束画面。
- 叙事收益：将“同频”从文案转化为身体化操作体验。

## 7. 验收指标（Definition of Done）

每个新交互方案上线前需满足：

1. **剧情一致性**：评审成员可清楚回答“此交互在表达哪段关系变化”。  
2. **可读性**：80% 首测玩家无需教程即可完成基础操作。  
3. **情绪命中**：测试问卷中目标情绪命中率 >= 70%。  
4. **节奏完整**：交互不打断叙事，且能自然衔接下一场景。  
5. **可跳过安全**：跳过后剧情与状态不破坏流程。  

---

## 8. 工作方式（执行节奏）

- 周初：剧情节拍拆解 + 玩法假设。
- 周中：低保真原型 + 5 人试玩。
- 周末：复盘数据 + 调整交互与反馈语言。
- 每轮迭代优先处理：  
  **“不贴剧情” > “不可读” > “不够新颖”**。
